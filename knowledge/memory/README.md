# 业务运行记忆

`knowledge/memory/` 用来沉淀业务运行过程中，经 Claude 与使用者交互后确认下来的案例、判断、例外处理和规则线索，供后续 `/init` 和规则完善复用。

这不是开发日志目录。

- 开发过程留档放在 `.ai_state/`
- 技术运行日志放在 `logs/service.log`
- 这里存放的是未来业务运行中的业务记忆

## 目录约定

- 固定路径：`knowledge/memory/YYYY/MM/YYYY-MM-DD.md`
- 拆分规则：一年一个目录，一月一个目录，一天一个 Markdown 文件
- 内容原则：只记录业务运行里有复用价值的结论，不记录代码改动、调试过程或开发进展

## 推荐结构

每个日记忆文件建议保持以下章节：

1. `## 当日概览`
2. `## 业务事件记录`
3. `## 规则命中与处理`
4. `## 人工确认与例外`
5. `## 可沉淀业务记忆`
6. `## 待固化规则`
7. `## 关联资料`

## 使用建议

- 只沉淀未来还会复用的业务判断，不复制整段会话。
- 优先记录“为什么这样判”“人工最后怎么确认”“以后遇到同类场景怎么处理”。
- 涉及制度缺口、规则冲突或高频例外时，单独写进“待固化规则”。
- 后续如由 Claude 自动追加，建议只写入已确认的业务结论，不要把普通问答或技术调试直接落盘。
