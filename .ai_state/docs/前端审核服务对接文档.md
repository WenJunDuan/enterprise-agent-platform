# 前端审核服务对接文档

本地审核服务对前端提供 4 个核心接口。前端只需要：

1. 带 token
2. 提交任意表单数据与可选附件
3. 查看任务列表或轮询任务状态
4. 拉取最终结果

---

## 1. 接口总览

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | `POST` | `/audit/submit` | 提交一次审核任务 |
| 2 | `GET`  | `/audit/tasks` | 查询任务列表（首页表格用） |
| 3 | `GET`  | `/audit/tasks/{request_id}` | 查询任务状态（轮询用） |
| 4 | `GET`  | `/audit/tasks/{request_id}/result` | 拉取最终审核结果 |

调用时序：

```
前端 ──POST /audit/submit──▶ 后端   → 返回 { request_id, status: "accepted" }
前端 ──GET  /audit/tasks──▶        → 展示任务列表（可选）
前端 ──GET  /audit/tasks/{id}──▶   → 循环直到 status in ("completed","failed")
前端 ──GET  /audit/tasks/{id}/result──▶ 渲染结果
```

## 2. 开始前

### 2.1 启动后端

```bash
# 本地开发模式
uv run python -m server.cli serve

# 或作为常驻服务
uv run app-server start
```

默认监听 `127.0.0.1:8000`。

### 2.2 base URL & token

| 项 | 值 |
|---|---|
| base URL (本地) | `http://127.0.0.1:8000` |
| Authorization | `Bearer sk-your-tenant-token` |
| 租户标识 | 服务端从 token 反查，无需前端传 |

> 本地 React UI 联调可以把 token 写到 `ui/.env.local` 的 `VITE_TENANT_TOKEN`；现场系统或接口对接方不使用 `VITE_*`，直接在 HTTP 请求头传 `Authorization: Bearer <tenant-token>`。

业务接口都必须带 `Authorization: Bearer <tenant-token>`，否则返回 `401`。`GET /health` 不需要鉴权。

### 3.2 附件样本从哪来

- **有附件场景**：任意一张 PNG / JPG 截图、PDF 扫描件、表格、订单导出都可以。
  - mac：`Command+Shift+4` 截图得到 png
  - 任何一张手机拍的发票照片（jpg/jpeg/webp）
  - 真实业务发票 PDF
- 服务端不按业务扩展名白名单拦截，文件名会做安全归一化

- 空文件（0 字节）会被拒，返回 `400 Uploaded file cannot be empty`

### 3.3 想看后端真实落盘的样子

```
data/submissions/{request_id}/<保留的附件文件>
```

前端联调遇到疑似字段缺失、编码问题，直接看这个 JSON 就能定位。

## 4. 接口详情

### 4.1 `POST /audit/submit`

**请求头**

```http
Authorization: Bearer <token>
Content-Type: multipart/form-data   # 浏览器使用 FormData 时会自动填
```

**请求字段**（均为 multipart part）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mode` | text | 是 | 固定传 `upload` |
| `form_json` | text | 否 | 业务表单对象经 `JSON.stringify()` 后的字符串；传入时必须是 JSON object |
| `files` | file | 否 | 附件。0 个或多个，多附件时重复同名 part |
| 其他文本字段 | text | 否 | 除 `mode` / `form_json` / `files` 外都会归档到 `fields` |

**`form_json` 业务字段**

后端不定义也不校验业务字段。下表只是当前报销 UI 模板会发送的示例字段，其他公司/业务线可以传完全不同的字段。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `case_id` | string | 否 | 业务单号或前端生成的唯一编号 |
| `applicant_name` | string | 否 | 报销申请人姓名 |
| `expense_type` | string | 否 | 费用大类，如 "业务招待" / "差旅报销" |
| `department` | string | 否 | 所属部门 |
| `expense_category` | string | 否 | 费用子类 |
| `biz_date` | string | 否 | 业务日期，建议 `YYYY-MM-DD` |
| `meal_period` | string | 否 | "中午" / "晚上" |
| `participants_total` | number | 否 | 总参与人数 |
| `internal_participants` | number | 否 | 内部参与人数 |
| `client_count` | number | 否 | 客户人数 |
| `city` | string | 否 | 业务发生城市 |
| `description` | string | 否 | 业务描述 |
| `business_purpose` | string | 否 | 业务目的 |
| `currency` | string | 否 | 币种，通常 `CNY` |
| `notes` | string | 否 | 备注 |

**响应示例** （HTTP 200）

```json
{
  "request_id": "faf62e3a-fa35-4d47-acd6-93b74190fe46",
  "status": "accepted",
  "mode": "upload",
  "task_status_url": "/audit/tasks/faf62e3a-fa35-4d47-acd6-93b74190fe46"
}
```

> `accepted` 只代表任务已创建、未开始或正在执行。前端拿 `request_id` 后必须轮询状态接口。

### 4.2 `GET /audit/tasks`

**请求头**：`Authorization`

**Query 参数**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `status` | string | 否 | 可选过滤：`accepted` / `running` / `completed` / `failed` |
| `limit` | number | 否 | 默认 20，范围 1-100 |
| `offset` | number | 否 | 默认 0 |

**响应示例**

```json
[
  {
    "request_id": "faf62e3a-fa35-4d47-acd6-93b74190fe46",
    "status": "running",
    "mode": "upload",
    "claim_id": null,
    "error_detail": null,
    "progress_message": "正在调用 Claude 审核",
    "submitted_at": "2026-04-13T09:27:31.691389+00:00",
    "started_at": "2026-04-13T09:27:32.100000+00:00",
    "finished_at": null,
    "updated_at": "2026-04-13T09:27:32.100000+00:00"
  }
]
```

### 4.3 `GET /audit/tasks/{request_id}`

**请求头**：`Authorization`

**响应示例**

```json
{
  "request_id": "faf62e3a-fa35-4d47-acd6-93b74190fe46",
  "status": "running",
  "mode": "upload",
  "claim_id": null,
  "error_detail": null,
  "progress_message": "正在调用 Claude 审核",
  "submitted_at": "2026-04-13T09:27:31.691389+00:00",
  "started_at":  "2026-04-13T09:27:32.100000+00:00",
  "finished_at": null,
  "updated_at":  "2026-04-13T09:27:31.691389+00:00"
}
```

**状态机**

| status | 含义 | 前端处理 |
|---|---|---|
| `accepted` | 已排队、未开始 | 继续轮询 |
| `running` | 正在审核 | 继续轮询，可展示 `progress_message` |
| `completed` | 完成 | 调 `/result` 接口 |
| `failed` | 失败 | 展示 `error_detail` |

轮询建议：2 秒一次，超时阈值按业务场景（推荐 3 分钟）。

### 4.4 `GET /audit/tasks/{request_id}/result`

只有 `status == completed` 时才会返回 200，否则：

- 未完成：`409 Audit task is not completed yet`
- 找不到：`404 Audit result not found`

**响应示例**

```json
{
  "claim_id": "DEMO-20260413-001",
  "verdict": "manual_review",
  "result": false,
  "conclusion": "待人工复核",
  "explanation": "根据现有材料，当前无法自动闭合审核结论，需要补充或人工确认。",
  "reasons": ["缺少关键辅助材料"],
  "policy_refs": ["expense.travel.001"],
  "risk_score": 65,
  "extracted_data": {},
  "evidence_chain": [],
  "reviewed_by": "expense-auditor",
  "timestamp": "2026-04-13T10:00:00+00:00"
}
```

**关键字段**

| 字段 | 类型 | 说明 |
|---|---|---|
| `verdict` | string | `approved` / `rejected` / `manual_review` |
| `result` | boolean | 是否通过 |
| `conclusion` | string | 结论一句话 |
| `explanation` | string | 展开说明 |
| `reasons` | string[] | 结论依据 |
| `policy_refs` | string[] | 命中的本地制度条款 ID |
| `risk_score` | number | 风险分 0-100 |
| `extracted_data` | object | 从附件/表单中抽取的结构化数据 |
| `evidence_chain` | object[] | 每条证据 → 条款的映射 |
| `reviewed_by` | string | 执行审核的 agent 名 |

## 5. Postman 对接（手动调通一次）

### 5.1 新建 Collection

1. 左侧新建 Collection `AuditAPI`
2. 在 Collection → `Variables` 里加两个变量：

| Key | Initial Value | Current Value |
|---|---|---|
| `baseUrl` | `http://127.0.0.1:8000` | 同 |
| `token` | `sk-your-tenant-token` | 同 |

3. Collection → `Authorization`：类型选 `Bearer Token`，Token 填 `{{token}}`。子请求默认继承。

### 5.2 请求 1：提交审核（单附件）

- Method: `POST`
- URL: `{{baseUrl}}/audit/submit`
- Body 选 `form-data`：

| KEY | TYPE | VALUE |
|---|---|---|
| `mode` | Text | `upload` |
| `form_json` | Text | 把 §3.1 示例 JSON 一行化后粘贴，可省略 |
| `files` | File | 选择本地发票 PDF 或截图 PNG |

点 `Send`。期望 HTTP 200，响应里有 `request_id`。

**保存 request_id 到变量**（自动化的关键）：在请求的 `Tests` 里加：

```js
const body = pm.response.json();
pm.collectionVariables.set("requestId", body.request_id);
```

### 5.3 请求 2：提交审核（多附件）

复制请求 1 重命名为 `submit-with-files`，在 form-data 里**追加**多行：

| KEY | TYPE | VALUE |
|---|---|---|
| `mode` | Text | `upload` |
| `form_json` | Text | 表单 JSON |
| `files` | File | 选择本地发票 PDF |
| `files` | File | 选择另一张截图 PNG |

> 多附件的要点：KEY 名**重复** `files`，TYPE 切到 `File`。Postman 会自动构造多 part。

### 5.4 请求 3：查询任务状态

- Method: `GET`
- URL: `{{baseUrl}}/audit/tasks/{{requestId}}`
- Send。看 `status` 字段。未完成就多发几次；完成后进入请求 4。

### 5.5 请求 4：拉取最终结果

- Method: `GET`
- URL: `{{baseUrl}}/audit/tasks/{{requestId}}/result`

如果 409，说明任务还没完成，回请求 3 继续轮询。

### 5.6 Postman 常见坑

- **不要手动在 Headers 里设 `Content-Type: multipart/form-data`**。Postman 选 form-data 后会自动加带 boundary，手动设会破坏。
- **form-data vs x-www-form-urlencoded**：后端只吃 `multipart/form-data`，选错会 415。
- **File 类型字段必须切 TYPE = File**，默认是 Text 会被当字符串发。

## 6. 代码对接（TypeScript 完整模板）

### 6.1 通用 client

```ts
// src/api/auditClient.ts
const BASE_URL = import.meta.env.VITE_API_BASE ?? "/";
const TOKEN    = import.meta.env.VITE_TENANT_TOKEN ?? "";

const authHeaders = (): Record<string, string> => ({
  Authorization: `Bearer ${TOKEN}`,
});

export type AuditForm = Record<string, unknown>;

export interface AuditSubmitAccepted {
  request_id: string;
  status: "accepted";
  mode: "upload" | "directory";
  task_status_url: string;
}

export type TaskStatus = "accepted" | "running" | "completed" | "failed";

export interface AuditTask {
  request_id: string;
  status: TaskStatus;
  mode: "upload" | "directory";
  claim_id: string | null;
  progress_message: string | null;
  error_detail: string | null;
  submitted_at: string;
  started_at: string | null;
  finished_at: string | null;
  updated_at: string;
}

export interface AuditResult {
  claim_id: string;
  verdict: "approved" | "rejected" | "manual_review";
  result: boolean;
  conclusion: string;
  explanation: string;
  reasons: string[];
  policy_refs: string[];
  risk_score: number;
  extracted_data: Record<string, unknown>;
  evidence_chain: Array<Record<string, unknown>>;
  reviewed_by: string;
  timestamp: string;
}
```

### 6.2 提交（单附件 / 多附件同一个函数）

```ts
export async function submitAudit(
  form: Record<string, unknown> | null,
  files: File[] = [],
): Promise<AuditSubmitAccepted> {
  const fd = new FormData();
  fd.append("mode", "upload");
  if (form) fd.append("form_json", JSON.stringify(form));
  for (const f of files) fd.append("files", f);  // 多附件重复 append

  const res = await fetch(`${BASE_URL}/audit/submit`, {
    method: "POST",
    headers: authHeaders(),   // 不要手设 Content-Type
    body: fd,
  });
  if (!res.ok) throw new Error(`submit ${res.status}: ${await res.text()}`);
  return res.json();
}
```

### 6.3 轮询状态

```ts
export async function getAuditTask(requestId: string): Promise<AuditTask> {
  const res = await fetch(`${BASE_URL}/audit/tasks/${requestId}`, {
    headers: authHeaders(),
  });
  if (!res.ok) throw new Error(`task ${res.status}`);
  return res.json();
}

export async function waitForAudit(
  requestId: string,
  { intervalMs = 2000, timeoutMs = 180_000 } = {},
): Promise<AuditTask> {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const task = await getAuditTask(requestId);
    if (task.status === "completed" || task.status === "failed") return task;
    await new Promise(r => setTimeout(r, intervalMs));
  }
  throw new Error(`audit timeout after ${timeoutMs}ms`);
}
```

### 6.4 拉取结果

```ts
export async function getAuditResult(requestId: string): Promise<AuditResult> {
  const res = await fetch(`${BASE_URL}/audit/tasks/${requestId}/result`, {
    headers: authHeaders(),
  });
  if (res.status === 409) throw new Error("任务未完成");
  if (!res.ok) throw new Error(`result ${res.status}`);
  return res.json();
}
```

### 6.5 页面层串起来

```ts
async function handleSubmit(form: AuditForm, files: File[]) {
  const { request_id } = await submitAudit(form, files);
  ui.showPending(request_id);

  const task = await waitForAudit(request_id);
  if (task.status === "failed") {
    ui.showError(task.error_detail ?? "审核失败");
    return;
  }

  const result = await getAuditResult(request_id);
  ui.showResult(result);
}
```

## 7. 常见错误

错误响应现在除了保留原有 `detail` 以外，还会统一返回一个结构化 `error` 对象：

```json
{
  "detail": "Audit task not found",
  "error": {
    "code": "not_found",
    "message": "Audit task not found",
    "status_code": 404,
    "path": "/audit/tasks/req-missing",
    "correlation_id": "f7d7d6e6f0a64f72b7d00cbf13f7e3d3"
  }
}
```

前端建议：

- 展示文案优先用 `error.message`，兼容旧逻辑时可以继续 fallback 到 `detail`
- 把 `error.correlation_id` 一并打到前端日志里，排查会快很多

### 提交阶段

| HTTP | detail | 原因 |
|---|---|---|
| 401 | `Missing Authorization header` | 没带 `Authorization` |
| 401 | `Authorization header must use Bearer token` | `Authorization` 不是 Bearer 格式 |
| 401 | `Invalid tenant token` | tenant token 不匹配 |
| 400 | `Invalid form_json` | `form_json` 不是合法 JSON |
| 400 | `form_json must decode to a JSON object` | `form_json` 解析出来不是对象 |
| 400 | `upload mode requires form_json, form fields, or files` | 上传模式没有任何有效内容 |
| 400 | `Uploaded file cannot be empty` | 上传了 0 字节文件 |
| 415 | `Unsupported Content-Type` | 请求既不是 multipart 也不是 json |

### 查询阶段

| HTTP | detail | 原因 |
|---|---|---|
| 404 | `Audit task not found` | `request_id` 不存在 |
| 409 | `Audit task is not completed yet` | 任务未到终态，继续轮询 |
| 404 | `Audit result not found` | 完成态但结果缺失，提示后端排查 |

## 8. 对接自检清单

- [ ] base URL、tenant token 已配置；本地 UI 用 `VITE_TENANT_TOKEN`，外部接口调用直接发 `Authorization`
- [ ] 页面顶部连接条显示 `/health` 可访问
- [ ] 请求头都带 `Authorization: Bearer <token>`
- [ ] 提交用 `FormData`，没有手设 `Content-Type`
- [ ] `form_json` 传的是字符串（已经 `JSON.stringify`）
- [ ] 附件字段名是 `files`，多附件重复 append；无附件也允许提交
- [ ] 拿到 `request_id` 后走轮询，未轮询到 `completed` 不要直接拿结果
- [ ] `failed` 状态显示 `error_detail`
- [ ] 结果页展示 `conclusion` / `explanation` / `reasons` / `policy_refs` / `risk_score` / `risk_dimensions` / `evidence_chain`
- [ ] 列表页可清空本机摘要，验证后端紧凑任务字段 fallback
