# 前端审核服务对接文档

本地审核服务对前端暴露 4 个核心接口。对接方只需：带 token → 提交表单数据与可选附件 → 轮询任务状态 → 拉取结果。

## 1. 接口总览

| # | 方法 | 路径 | 用途 |
|---|---|---|---|
| 1 | `POST` | `/audit/submit` | 提交一次审核任务 |
| 2 | `GET`  | `/audit/tasks` | 任务列表（首页表格） |
| 3 | `GET`  | `/audit/tasks/{request_id}` | 任务状态（轮询） |
| 4 | `GET`  | `/audit/tasks/{request_id}/result` | 最终审核结果 |

```
POST /audit/submit            → { request_id, status: "accepted" }
GET  /audit/tasks/{id}        → 轮询直到 status ∈ ("completed","failed")
GET  /audit/tasks/{id}/result → 渲染结果
```

`GET /health` 无需鉴权，供连接探活。

## 2. 准备

### base URL & token

| 项 | 值 |
|---|---|
| base URL（本地） | `http://127.0.0.1:8000` |
| 鉴权头 | `Authorization: Bearer <tenant-token>` |
| 租户标识 | 服务端从 token 反查，前端不用传 |

- 业务接口都必须带 `Authorization`，否则 `401`；`GET /health` 例外。
- 本地 React 联调可把 token 写进 `ui/.env.local` 的 `VITE_TENANT_TOKEN`；外部系统对接直接发 `Authorization` 头，不要用 `VITE_*`。

启动后端：

```bash
uv run python -m server.cli serve      # 开发模式
uv run app-server start                # 常驻服务
```

### CORS

默认只放行 `http://localhost:5173`、`http://127.0.0.1:5173`。部署到其他域名时，把目标 origin 加进 `server/api.py` 的 `CORSMiddleware.allow_origins`（或用反向代理与前端同源）。

### 路径白名单

后端只对**已注册路由**返回结构化业务错误；任何**未注册路径**直接返回最小化的 `404 {"detail":"Not Found"}`，不带 `error` 子对象。前端读 `error` 字段前先判空（见 §5）。

## 3. 接口详情

### 3.1 `POST /audit/submit`

请求头：`Authorization: Bearer <token>` + `Content-Type: multipart/form-data`（浏览器用 `FormData` 时自动带 boundary，**不要手设**）。

请求字段（multipart part）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `mode` | text | 是 | `upload`（前端常用）或 `directory`（见下） |
| `form_json` | text | 否 | 业务表单对象 `JSON.stringify()` 后的字符串，必须解析为 JSON object |
| `files` | file | 否 | 附件，0 个或多个；多附件重复同名 part |
| 其他文本字段 | text | 否 | 除上述外都会归档到 `fields` |

**`form_json` 是自由结构**：后端不定义、不校验业务字段，不同业务线可传完全不同的字段。常见报销字段如 `case_id` / `applicant_name` / `expense_type` / `department` / `biz_date` / `currency` / `description` 等均为可选。

**发票 OCR 直接传 JSON**：可把发票 OCR 的结构化结果放进 `form_json`，附件照常用 `files` 上传，两者都会进入审核材料。建议放在独立键下（如 `invoice_ocr`）以便区分来源。注意 `form_json` 属于**申报方提供的数据**，审核会将其与附件、本地规则交叉核对，不作为已核验事实——"OCR 写了"不等于"过审"。

```jsonc
// form_json 示例（含 OCR）
{
  "case_id": "DEMO-20260413-001",
  "applicant_name": "张三",
  "expense_type": "业务招待",
  "currency": "CNY",
  "invoice_ocr": {
    "invoice_no": "0123456789",
    "amount": 880.00,
    "seller": "XX餐饮有限公司",
    "date": "2026-04-13"
  }
}
```

附件约束：不按扩展名白名单拦截，文件名会安全归一化；单文件上限 `MAX_UPLOAD_FILE_BYTES`（默认 10 MiB）；0 字节文件返回 `400`。

响应（HTTP 200）：

```json
{
  "request_id": "faf62e3a-fa35-4d47-acd6-93b74190fe46",
  "status": "accepted",
  "mode": "upload",
  "task_status_url": "/audit/tasks/faf62e3a-fa35-4d47-acd6-93b74190fe46"
}
```

> `accepted` 仅代表任务已创建，**必须轮询状态接口**取终态。

**`directory` 模式**（本地批跑/服务端目录扫描，前端一般用不到）：改用 `Content-Type: application/json`，body `{ "mode": "directory", "directory_path": "data/your-sample" }`。`directory_path` 必须存在且位于项目根 `data/` 下，不接受附件与 `form_json`，响应结构同 `upload`。

### 3.2 `GET /audit/tasks`

Query：`status`（`accepted`/`running`/`completed`/`failed`，可选）、`limit`（默认 20，1-100）、`offset`（默认 0）。

响应为任务对象数组，单个对象结构同 §3.3。

### 3.3 `GET /audit/tasks/{request_id}`

```json
{
  "request_id": "faf62e3a-fa35-4d47-acd6-93b74190fe46",
  "status": "running",
  "mode": "upload",
  "claim_id": null,
  "error_detail": null,
  "progress_message": "正在调用 Claude 审核",
  "submitted_at": "2026-04-13T09:27:31.691389+00:00",
  "started_at": "2026-04-13T09:27:32.100000+00:00",
  "finished_at": null,
  "updated_at": "2026-04-13T09:27:32.100000+00:00"
}
```

状态机：

| status | 含义 | 前端处理 |
|---|---|---|
| `accepted` | 已排队、未开始 | 继续轮询 |
| `running` | 正在审核 | 继续轮询，可展示 `progress_message` |
| `completed` | 完成 | 调 `/result` |
| `failed` | 失败 | 展示 `error_detail` |

> 轮询建议 2 秒一次。后端 `AUDIT_TASK_RUNNING_TIMEOUT_SECONDS` 默认 600 秒才会把 stale 任务回收为 `failed`，前端超时阈值应 ≥ 6 分钟，否则会先于服务端断开、看不到终态。

### 3.4 `GET /audit/tasks/{request_id}/result`

仅 `status == completed` 时返回 200；未完成 `409 Audit task is not completed yet`；缺失 `404 Audit result not found`。

```json
{
  "claim_id": "DEMO-20260413-001",
  "verdict": "manual_review",
  "result": false,
  "conclusion": "待人工复核",
  "explanation": "根据现有材料，当前无法自动闭合审核结论，需要补充或人工确认。",
  "reasons": ["缺少关键辅助材料"],
  "policy_refs": ["expense.travel.001"],
  "risk_score": 65,
  "manual_review_reason": "insufficient_evidence",
  "risk_dimensions": [
    { "name": "invoice", "score": 6 },
    { "name": "approval", "score": 4 }
  ],
  "extracted_data": {},
  "evidence_chain": [],
  "reviewed_by": "expense-auditor",
  "timestamp": "2026-04-13T10:00:00+00:00"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `verdict` | string | `approved` / `rejected` / `manual_review` |
| `result` | boolean | 是否通过 |
| `conclusion` | string | 结论一句话 |
| `explanation` | string | 展开说明 |
| `reasons` | string[] | 结论依据 |
| `policy_refs` | string[] | 命中的本地制度条款 ID |
| `risk_score` | number | 风险分 0-100 |
| `manual_review_reason` | string \| null | 复核原因码：`data_conflict` / `pre_approval_mismatch` / `missing_approval` / `invoice_invalid` / `insufficient_evidence` / `rule_gap` / `budget_exceeded` |
| `risk_dimensions` | object[] | 分维度风险，每项 `{ name, score(0-10) }`，name ∈ `invoice/amount/approval/budget/anomaly` |
| `extracted_data` | object | 从附件/表单抽取的结构化数据 |
| `evidence_chain` | object[] | 每条证据 → 条款的映射 `{ source, finding, conclusion }` |
| `reviewed_by` | string | 执行审核的 agent 名 |

### 3.5 `GET /health`（无需鉴权）

```json
{ "status": "ok", "app_server": { "ok": true, "running": true }, "failing_checks": [], "advisories": [] }
```

`status` 非 `ok` 时 HTTP 返 `503`。`failing_checks` 是失败的子检查名清单，`advisories` 是非阻塞提示。

## 4. TypeScript 对接模板

```ts
// auditClient.ts
const BASE_URL = import.meta.env.VITE_API_BASE ?? "/";
const TOKEN    = import.meta.env.VITE_TENANT_TOKEN ?? "";
const authHeaders = (): Record<string, string> => ({ Authorization: `Bearer ${TOKEN}` });

export type TaskStatus = "accepted" | "running" | "completed" | "failed";

export interface AuditTask {
  request_id: string;
  status: TaskStatus;
  mode: "upload" | "directory";
  claim_id: string | null;
  progress_message: string | null;
  error_detail: string | null;
  submitted_at: string;
  started_at: string | null;
  finished_at: string | null;
  updated_at: string;
}

export interface AuditResult {
  claim_id: string;
  verdict: "approved" | "rejected" | "manual_review";
  result: boolean;
  conclusion: string;
  explanation: string;
  reasons: string[];
  policy_refs: string[];
  risk_score: number;
  manual_review_reason: string | null;
  risk_dimensions: Array<{ name: string; score: number }>;
  extracted_data: Record<string, unknown>;
  evidence_chain: Array<{ source: string; finding: string; conclusion: string }>;
  reviewed_by: string;
  timestamp: string;
}

// 提交（单/多附件同一函数）
export async function submitAudit(
  form: Record<string, unknown> | null,
  files: File[] = [],
): Promise<{ request_id: string; status: "accepted" }> {
  const fd = new FormData();
  fd.append("mode", "upload");
  if (form) fd.append("form_json", JSON.stringify(form));  // OCR 可放进 form
  for (const f of files) fd.append("files", f);            // 多附件重复 append
  const res = await fetch(`${BASE_URL}/audit/submit`, {
    method: "POST",
    headers: authHeaders(),   // 不要手设 Content-Type
    body: fd,
  });
  if (!res.ok) throw new Error(`submit ${res.status}: ${await res.text()}`);
  return res.json();
}

// 轮询直到终态
export async function waitForAudit(
  requestId: string,
  { intervalMs = 2000, timeoutMs = 360_000 } = {},
): Promise<AuditTask> {
  const deadline = Date.now() + timeoutMs;
  while (Date.now() < deadline) {
    const res = await fetch(`${BASE_URL}/audit/tasks/${requestId}`, { headers: authHeaders() });
    if (!res.ok) throw new Error(`task ${res.status}`);
    const task: AuditTask = await res.json();
    if (task.status === "completed" || task.status === "failed") return task;
    await new Promise(r => setTimeout(r, intervalMs));
  }
  throw new Error(`audit timeout after ${timeoutMs}ms`);
}

// 拉结果
export async function getAuditResult(requestId: string): Promise<AuditResult> {
  const res = await fetch(`${BASE_URL}/audit/tasks/${requestId}/result`, { headers: authHeaders() });
  if (res.status === 409) throw new Error("任务未完成");
  if (!res.ok) throw new Error(`result ${res.status}`);
  return res.json();
}

// 页面串联
async function handleSubmit(form: Record<string, unknown>, files: File[]) {
  const { request_id } = await submitAudit(form, files);
  const task = await waitForAudit(request_id);
  if (task.status === "failed") return ui.showError(task.error_detail ?? "审核失败");
  ui.showResult(await getAuditResult(request_id));
}
```

curl 快速验证：

```bash
curl -X POST http://127.0.0.1:8000/audit/submit \
  -H "Authorization: Bearer sk-your-tenant-token" \
  -F "mode=upload" \
  -F 'form_json={"case_id":"CLI-002","invoice_ocr":{"invoice_no":"012","amount":880}}' \
  -F "files=@/path/to/receipt.png"
```

## 5. 错误处理

命中已注册路由的业务错误，除保留 `detail` 外统一返回结构化 `error`：

```json
{
  "detail": "Audit task not found",
  "error": {
    "code": "not_found",
    "message": "Audit task not found",
    "status_code": 404,
    "path": "/audit/tasks/req-missing",
    "correlation_id": "f7d7d6e6f0a64f72b7d00cbf13f7e3d3"
  }
}
```

每条响应都带 `X-Request-ID` 头，与 `error.correlation_id` 同值，建议打到日志便于排查。

- 文案优先用 `error.message`，旧逻辑可 fallback 到 `detail`。
- **读 `error` 子字段前先判空**：路径白名单拦下的请求只有 `{"detail":"Not Found"}`，没有 `error`。

| HTTP | detail | 原因 |
|---|---|---|
| 503 | `Server is not configured with tenant keys` | 服务端 `TENANT_KEYS` 仍为默认且未开 `ALLOW_INSECURE_DEFAULT_TENANT_KEY` |
| 401 | `Missing Authorization header` / `... must use Bearer token` / `Invalid tenant token` | 鉴权问题 |
| 400 | `Invalid form_json` / `form_json must decode to a JSON object` | `form_json` 不是合法 JSON 对象 |
| 400 | `upload mode requires form_json, form fields, or files` | 上传模式无任何有效内容 |
| 400 | `Uploaded file cannot be empty` | 上传 0 字节文件 |
| 415 | `Unsupported Content-Type` | 既不是 multipart 也不是 json |
| 404 | `Audit task not found` | `request_id` 不存在 |
| 409 | `Audit task is not completed yet` | 未到终态，继续轮询 |
| 404 | `Audit result not found` | 完成态但结果缺失，提示后端排查 |
| 404 | `{"detail":"Not Found"}`（无 `error`） | 请求了未注册路径，见 §2 路径白名单 |
| 405 | 标准业务错误结构 | 路径存在但方法不对 |

## 6. 对接自检清单

- [ ] base URL、tenant token 已配置（本地 UI 用 `VITE_TENANT_TOKEN`，外部对接直接发 `Authorization`）
- [ ] 连接条显示 `/health` 可访问
- [ ] 所有业务请求带 `Authorization: Bearer <token>`
- [ ] 提交用 `FormData`，未手设 `Content-Type`
- [ ] `form_json` 是 `JSON.stringify` 后的字符串；OCR 数据放独立键
- [ ] 附件字段名 `files`，多附件重复 append；无附件也可提交
- [ ] 拿 `request_id` 后轮询，未到 `completed` 不直接取结果；超时阈值 ≥ 6 分钟
- [ ] `failed` 显示 `error_detail`
- [ ] 结果页展示 `conclusion` / `explanation` / `reasons` / `policy_refs` / `risk_score` / `risk_dimensions` / `evidence_chain`
