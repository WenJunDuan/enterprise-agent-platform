# 评标服务对接文档（iframe 嵌入版）

> 场景：对方系统页面有「AI 分析」按钮，点击后把**招标文件**与**投标文件**经接口提交、
> 调用**开始分析**，随后以 **iframe 嵌入**本平台评标页面展示进度与结论。
> 本版只保留该场景所需内容；旧版（报销审核 `/audit` + OCR 接口）见 git 历史（2026-08-20 前版本）。

## 1. 一次分析的调用序

```
0. POST /tender/projects                        建招标项目（幂等，可复用）→ project_id
1. POST /tender/projects/{id}/tender-doc        上传招标文件 → 后台自动 OCR + 解析评分标准
2. POST /tender/projects/{id}/bids              上传投标文件 → bid_id（必须保存）
3. POST /tender/projects/{id}/evaluate          开始分析（带 bid_id）→ request_id
之后进度与结论由 iframe 页面展示，无需再对接口。
```

**关键语义（收单等就绪）**：第 3 步**不必等**第 1/2 步的后台解析完成——解析中提交照收，
任务会等底稿与评分标准就绪后自动开跑（服务端等待上限 600 秒，等不到则任务明确失败并给原因）。
按钮点击后四步可连续发出。

## 2. 准备

| 项 | 值 |
|---|---|
| base URL（推荐） | `http://<前端主机>/tender/...`（前端 nginx 已同源代理到后端，与 iframe 同源、浏览器直调免 CORS） |
| base URL（直连） | `http://<后端主机>:<端口>/tender/...`（仅服务端对服务端；浏览器直调需加 CORS 白名单） |
| 鉴权 | 所有接口带 `Authorization: Bearer <tenant-token>`（token 由我方发放），缺失/错误 `401` |
| 探活 | `GET /health`（无需鉴权） |
| 上传 | `multipart/form-data`，文件字段名 `files`（可重复多文件）；单文件默认上限 256 MiB（`MAX_UPLOAD_FILE_BYTES` 可调），nginx 层 512 MB |

## 3. 接口详情

### 3.0 建招标项目 `POST /tender/projects`

`Content-Type: application/json`，字段全部可选：

```json
{ "tender_no": "ZB-2026-001", "title": "××采购项目", "tenderee": "××单位" }
```

响应含 `project_id`（后续三步都用它）。**幂等**：同租户同 `tender_no` 重复调用返回既有项目，
不会建重——对方系统可放心在每次按钮点击时都先调一次。

### 3.1 上传招标文件 `POST /tender/projects/{project_id}/tender-doc`

multipart：`files`（≥1 个，PDF/Word 均可）。响应：

```json
{ "project_id": "tp-xxxx", "ocr_status": "running" }
```

返回即受理，后台自动完成 OCR 与评分标准解析。同项目重传会覆盖并重新解析。

### 3.2 上传投标文件 `POST /tender/projects/{project_id}/bids`

multipart：`files`（≥1 个）+ 可选文本字段 `bidder_name`（投标单位名，建议传，页面展示用）。响应：

```json
{ "bid_id": "bid-xxxx", "ocr_status": "running" }
```

**`bid_id` 必须保存**，第 3 步要带。一家投标人调用一次；多家投标人各调一次、各得一个 `bid_id`。

### 3.3 开始分析 `POST /tender/projects/{project_id}/evaluate`

multipart，两个文本字段，**不必重传文件**（服务端复用已上传底稿）：

| 字段 | 值 |
|---|---|
| `mode` | `upload` |
| `form_json` | `JSON.stringify({ "bid_id": "<3.2 返回值>", "bidder_name": "<同 3.2>" })` |

响应：

```json
{ "request_id": "…", "status": "accepted", "mode": "upload", "task_status_url": "/tender/tasks/…" }
```

- `409`：评分标准解析已失败（重传招标文件后再试，错误里带具体原因）
- `503`：评标队列已满，稍后重试
- 漏传 `bid_id` 时服务端按 `bidder_name` 回查兜底，但请尽量传，兜底失败会退化成重新 OCR（慢约 5 分钟）

### 3.4 （可选）程序化取结果

只用 iframe 展示的话本节可以不接。若对方系统还想拿到结论数据：

- `GET /tender/tasks/{request_id}`：轮询 `status`（`accepted`/`running`/`completed`/`failed`），
  建议 2 秒一次，客户端超时阈值 ≥ 15 分钟
- `GET /tender/tasks/{request_id}/result`：`completed` 后返回完整结论 JSON
  （`verdict`、`extracted_data.scoring`（逐项评分）、`eligibility_checks`（资格审查）、
  `evidence_chain`（证据链）等；未完成 `409`）

## 4. iframe 嵌入

- **嵌入地址**：`http://<前端主机>/contracts/tender/list`（评标项目列表，可点进详情看分析进度与报告）。
  详情页支持 `?view=analysis|report` 参数。
- **示例**：

```html
<iframe src="http://<前端主机>/contracts/tender/list"
        style="width:100%;height:100vh;border:0"
        allow="clipboard-write"></iframe>
```

- **页面鉴权**：首次打开跳 PIN 输入页（`/otp`），输入我方分配的 PIN 后换取租户 token 存浏览器本地，
  同一浏览器后续免输。第三方 iframe 场景下浏览器按顶层站点分区存储：在对方系统域下输一次即可；
  用户清缓存/换浏览器需重输。
- **防嵌限制现状**：前端 nginx 未设 `X-Frame-Options` / CSP `frame-ancestors`，当前可被任意站点
  iframe。对外上线前建议在 nginx 加 `Content-Security-Policy: frame-ancestors <对方系统域名>` 白名单。

## 5. 错误速查

| HTTP | detail | 处置 |
|---|---|---|
| 401 | 鉴权类文案 | 检查 `Authorization: Bearer <token>` |
| 404 | `Tender project not found` | `project_id` 错误，或 token 对应租户与项目不符 |
| 400 | `必须至少上传 1 个文件` | `files` 字段为空 |
| 400 | `上传连接中断，请重新提交` | 网络中断，重传 |
| 409 | 评分标准解析失败类文案 | 重传招标文件（3.1）后再开始分析 |
| 503 | `评标队列已满，请稍后重试` | 退避重试 |
| 415 | `Unsupported Content-Type` | 上传用 multipart；建项目用 JSON |

业务错误响应带结构化 `error` 对象与 `X-Request-ID` 响应头（联系我方排查时提供该 ID）。

## 6. curl 快速验证

```bash
BASE=http://<前端主机>; TOKEN=sk-your-tenant-token

# 0. 建项目
curl -s -X POST $BASE/tender/projects -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"tender_no":"ZB-2026-001","title":"演示项目"}'

# 1. 上传招标文件
curl -s -X POST $BASE/tender/projects/<project_id>/tender-doc \
  -H "Authorization: Bearer $TOKEN" -F "files=@/path/招标文件.pdf"

# 2. 上传投标文件
curl -s -X POST $BASE/tender/projects/<project_id>/bids \
  -H "Authorization: Bearer $TOKEN" -F "bidder_name=某投标公司" -F "files=@/path/投标文件.pdf"

# 3. 开始分析
curl -s -X POST $BASE/tender/projects/<project_id>/evaluate \
  -H "Authorization: Bearer $TOKEN" -F "mode=upload" \
  -F 'form_json={"bid_id":"<bid_id>","bidder_name":"某投标公司"}'
```
