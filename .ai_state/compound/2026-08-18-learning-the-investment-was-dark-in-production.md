# Learning · 一个 sprint 的全部投资可以在生产里"整条是暗的"而无人察觉

- 日期: 2026-08-18
- 类型: learning

## 事实

2026-08-15 sprint 建的证据层（S3–S8：按评分项检索 + 续接 + 闭式预算，累计数千行代码、
四轮 review、三次全量回归）**在生产环境从未激活过一次**。用户报"结果很不准、时间很长"后
才查出来：它挂在一个前置上——`criteria`——而 criteria 的抽取一旦失败（模型没只输出 JSON），
整条投资就旁路，静默退回到它本要取代的那条老路（整份注入 + 腰斩截断）。

判定它"从未激活"的证据：全部历史评标日志里**零条** `tender_evidence_context_built`。
修复后第一次出现该日志，同时 `tender_context_truncated` 首次消失。

## 为什么没被更早发现

1. **单测全绿**：证据层自身的单元/集成测试一直是绿的——它们直接调 `build_evidence_context`
   并喂现成 criteria，从不经过"criteria 是否可得"这一层。
2. **降级是静默的**：criteria 无可检索项时 `return EvidenceContext()`，注释写着"不是失败，
   交回既有路径"——零日志零 warning。设计档 KD4 明写"降级必须留痕"，这条是漏网。
3. **状态字段说谎**：`criteria_status='ready'` 与 `criteria_error='抽取失败'` 并存，
   前端据 ready 放行，没人怀疑。
4. **没有"这条投资今天被用到了吗"的观测**：所有度量都是"它工作时表现如何"，
   没有一条是"它有没有在工作"。

## 判据（下次照做）

> **交付一条新路径时，必须同时交付"这条路径今天被走过几次"的可观测量**，
> 且该量要能在生产日志里一句 grep 判定。没有这个量，路径可以整条是暗的而全绿。

推论三条：

- **前置条件失败必须可见**：新路径依赖的每个前置（配置项 / 上游产物 / 状态字段），
  其缺失都要产出用户可见信号，不能只在代码注释里写"交回既有路径"。
- **状态字段与错误字段并存即缺陷**：`status=ready` 和 `error=失败` 能同时存在，说明写入点
  没有终态守卫。这类矛盾要在 store 层用原子语义排除，不能靠调用方自觉。
- **回落路径的质量要单独测**：本次回落路径（整份注入 + 关键词截断）的关键词表全是**招标文件**
  术语，而被截的内容以**投标文件**为主——回落路径从设计上就取不到投标证据，却从没人测过它。
