# learning · 检索质量的判据只能落在命中块正文上，出处标签是独立失败面

## 踩到的坑

第三轮实跑看到 9 个评分项「9/9 命中、1ms」，但渲染出的出处行全是同一章：

```
企业综合实力 → 【投标文件·十、雷击事故应急预案】【第315页】
类似业绩     → 【投标文件·十、雷击事故应急预案】【第317页】
```

据此判定「**命中的是错误证据**，错误证据比缺失证据更危险」，写成阻塞项、给出三条根因初判
（BM25 长章节压制 / tag 过滤没用上 / 该按 basis 检索），并结论「不要部署」。

第四轮把命中块的**正文**打开，三条初判全错：

```
第315页 → 4.7.企业综合实力
第317页 → 4.8.类似业绩 + 3 行业绩表（项目名/合同金额/签订日期）
```

内容全部正确，且 trigram tokenizer 下 phrase 等价子串匹配——每条命中都字面含查询词，
BM25 排序压根不参与决定"命中了什么"。「业绩仅出现 1 次」这个计数也是对的，那 1 次就是
`4.8.类似业绩` 这个小节标题本身。

## 教训

**"检索到了什么"与"出处标签说它在哪"是两个独立的失败面，后者会伪装成前者。**

真缺陷是标签：投标用 `4.7./4.8.` 十进制编号，章节识别器不认，于是上级章节一路吞到 40 页后，
所有小节都挂在它名下。证据没错，出处错——但读者（包括我）先看到的是出处。

推论：**只看渲染产物无法判断检索质量**。渲染是"检索结果 + 标签"的合成物，两者任一错都长得一样。

## 可操作做法

1. 度量脚本必须同时报四个量，缺一个就会误判：**字面命中数(ground truth) / 检索返回数 /
   标签相符率 / 逐项注入字数**。前两者比出召回，后两者比出可用性。
   （落地：`scripts/measure_tender_evidence.py`）
2. 判定"命中错了"之前，**必须打印命中块正文**，不接受出处行作为内容证据。
3. 体积类代理指标会奖励垃圾。本轮 AC 一度写「全项注入 ≥20,000 字」，而 76 个注入块里 35 个是
   合同扫描件的页码残留（整块 14 字，而出处抬头比内容还长）——数字全绿、内容更糟。
   把判据换成**内容抽查**（"类似业绩必须取到业绩表 + 三份合同、且不串入下一评分项"）才抓得住。
