# Decision · 真实语料只清工作区，不重写 git 历史

- 日期: 2026-08-17
- 类型: decision
- 决策者: 用户（主 agent 提供影响面分析后拍板）

## 背景

pass3 E4 标出 1 个测试文件的 3 行含真实项目语料。全仓实测后发现范围是 **11 个文件**，
其中最严重的是**真人姓名（投标方拟派负责人）写在生产提示词 `.claude/commands/tender-evaluate.md`
的判分决策表 A7 里**，随每一次评标发给模型；另有真实公司名 2 个（前端测试 10 处）、
真实机构项目名 1 个、以及三处源码注释拿真实项目串举例。

该姓名 2026-06-19 由 `95a2f89`（新增招投标业务域）引入，跨 11 个 commit，**已推送 origin**。

## 决策：只清工作区

清工作区消除**活的暴露面**（模型每次评标看到的提示词、新 clone 拿到的文件、代码检索）；
重写历史额外消除的只是**考古式暴露面**（`git log -S` / GitHub blame 翻旧 commit）。

拒绝重写历史的理由（按权重）：

1. **会打断自己的 hash 锚定证据链**——`.ai_state` 内有 44 个可解析的真实 commit hash 引用
   （`tdd-evidence.yaml` 的 `baseline_commit`/`covered_code_commit`、handoff、design 实施修订），
   重写后全部悬空。这是铁律[证据与出处]的自伤。
2. 首次引入点 `95a2f89` 之后的**几乎全部 750 条历史都要换 hash**，需 force push 受保护分支
   ——违反 git-conventions 明令，且要走 ATHENA_ALLOW_PUSH。
3. **不保证彻底**：GitHub 侧旧对象可经 API/PR ref 存活；若仓库 public 且被 fork，
   fork network 内对象永久保留，重写清不掉。
4. 风险性质是「代码注释与举例中的一个中文姓名」，非凭证、非个人信息数据集。

若日后判定需要彻底消除（如对方为外部投标人且有合规要求），另开独立窗口做，
前提：确认无人基于该仓库工作 + 用户在场确认强推。备选低成本方案：仓库改 private。

## 配套（防复发）

纪律层已记 [[tender-generality-discipline]]（测试语料也算真实语料）；
机械层加 `tests/test_no_real_corpus.py` 组织名形态守卫——**守卫本身不得存真名**，
故用「组织名形态正则 + 合成名允许清单」实现，新混入的真实机构/公司名即刻翻红。
