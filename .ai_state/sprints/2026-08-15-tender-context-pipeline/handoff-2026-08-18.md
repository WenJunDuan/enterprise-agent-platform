## 二、本会话查清的根因链（已修）

用户实测：11.5 分钟、11 项只判出 2 项、"材料明明有却说要人工核验"、"找出来的和看到的对不上"。

```
① /tender-extract-info 抽取 criteria 失败（JSONContractError：模型没只输出 JSON）
② criteria 为空，但 criteria_status 被标 ready（状态谎报）→ 前端放行评标
③ criteria 为空 → 证据层（以 criteria 项为检索键）跳过
④ 静默退回整份注入 → 底稿 784,903 → 178,641 字节（砍 77%）
⑤ 截断按 KEY_SECTION_KEYWORDS 挑"关键章节"，而那 14 个词**全是招标文件术语**
   → 投标方的营业执照/社保/业绩/检测报告一个都不命中 → 优先被削
⑥ 模型只剩"规则"没有"证据" → 大面积 evidence_unresolved
⑦ 6 万 token 每轮重发 → 11.5 分钟
```

**附带查实的更严重问题**：那个只看到 23% 材料的会话，其自解析 criteria 被**回填成项目永久权威**
（首个写入者赢、不覆盖），后续每家投标都会继承。

**"上下文没对齐"的机制**（Agent 实测三种形态）：截断把非关键块替换为省略标记再拼回，
最严重一种是承载 `### 文件:` 头的块被削到 0 → `parse_corpus` 流式状态机丢弃整段 →
**60,178 字节底稿从 69 段变 0 段**，评分标准在上下文里但出处一条都回查不上。

## 七、本会话确立的纪律（长期有效）

1. **真实语料不得进代码与提示词**（用户原话：定向学单一标段、不通用）。测试语料匿名化但
   **必须保住触发缺陷的结构性质**（形近字对、连续重合字数、块长比例）。已加机械守卫
   `tests/test_no_real_corpus.py`（形态正则 + 合成名白名单，守卫自身不存真名）。
2. **不许按单份文档拟合**：不加关键词、不调阈值适配某文档。判据必须是链路级/语言级/物理级。
   `KEY_SECTION_KEYWORDS` 每出一次事故加一个词就是反面教材。
3. **状态字段不可轻信**：`criteria_status=ready` 与 `criteria_error=失败` 曾并存。
   改数据契约时回归面按**"谁构造这个结构"**选，不按"谁 import 这个模块"选。
4. **先部署实跑再补门禁**：runtime-verify 需部署机，是 review 的前置不是后置。
5. **杀后台进程要杀真正的子进程**：`kill` 外层 shell 不会停 pytest，本会话曾因此三个 pytest 并发。
