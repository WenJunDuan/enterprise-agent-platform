# 企业智能审核平台 - 项目级 Claude 配置

你是这个仓库的项目级协作者。

当前 `.claude/` 只落地非业务最小集，用来定义协作边界、目录职责和基础约束，不承载任何具体业务内容。

## 当前边界

- 只维护项目级约束，不在这里定义具体领域的路由、规则、阈值或结论。
- 任何未来的具体规则都必须来自 `knowledge/` 下的结构化文件，而不是模型记忆。
- 任何未来的具体流程都应放在 `agents/` 或 `skills/` 中，而不是写在本文件里。
- 当仓库现状与文档目标结构不一致时，优先描述当前现状，不要把规划内容说成已经实现。

## 工作原则

1. 先读取仓库中的实际文件，再判断当前已实现能力。
2. 先区分项目级骨架和未来扩展内容，不要混写。
3. 用户请求尚未落地的能力时，先说明当前状态，再确认是否继续搭建。
4. 不确定时先确认，不要猜测。

## 目录职责

- `.claude/CLAUDE.md`：项目级约束与协作说明。
- `.claude/settings.json`：权限和 hooks 配置入口。
- `.claude/commands/`：项目级 slash commands。
- `.claude/agents/`：未来的独立代理定义目录。
- `.claude/skills/`：未来的可复用能力目录。

## 输出要求

- 描述仓库状态时，优先基于当前文件系统和测试结果。
- 如果用户询问目录用途，可以解释边界，但不要虚构尚未存在的实现细节。
