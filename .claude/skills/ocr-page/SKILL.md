# ocr-page · 按需逐页 OCR

评标默认用服务端预处理的整份 OCR 底稿（已注入上下文）。**多数情况无需本技能**——底稿够用就直接引底稿。
仅在以下情况按需调用，把"全靠 server 预处理"补成"按需取证"：

## 何时用
- 某页是**扫描件/盖章/证书**，注入底稿里该页文字残缺或标了低置信（`evidence_resolution.low_clarity_files`）。
- 要**逐字核对一条证据的真实页码**（底稿 `【第N页】` 锚点），避免引印刷页号导致 `page_mismatch`。
- 底稿里定位不到、但你判断该材料应在投标某页 → 对该页重识别确认。

## 怎么用
```bash
uv run python .claude/skills/ocr-page/ocr.py <文件路径> [--pages N-M] [--seal]
```
- `<文件路径>`：投标/招标文件绝对路径（评标目录里的真实文件）。
- `--pages N-M`：只取底稿 `【第N页】` 锚点落在该区间的内容（如 `--pages 7` 或 `--pages 315-320`）。缺省=整份。
- `--seal`：该页含**印章/红章/证书**且普通识别读不清时加，启用印章 OCR（更慢，仅必要页用）。

## 读输出
- 输出是带 `【第N页】` 锚点的逐页文本；**引证据时页码 N 照抄这里的锚点数字**（不是文档印刷页号）。
- `[错误] …`（stderr，非 0 退出）→ 识别失败，按"读不清"窄情形降 `manual_review`（`insufficient_evidence`），**不要据此判 0**。

## 转换稿文件（Office → PDF）
底稿文件头标了 `route=convert, 已转换为PDF识别, 页号为转换稿页号`、锚点形如 `【转换稿第M页】` 的文件，
其页号属于 **LibreOffice 转换出的临时 PDF**，不是原 docx/xls 的页：

- **不能直接翻原件核锚**（Word 分页 ≠ LibreOffice 分页，页码对不上是正常的，不是识别错）。
- 要核这类页，须先用**同版本容器内的同参数 LibreOffice** 把原件转成 PDF（同镜像内确定性可复现），
  再对转换稿 PDF 跑本 skill；`--pages` 传的也是转换稿页号。
- 引证据时出处写 `文件名 转换稿第M页`，并给该条 `evidence_chain` 加 `"page_kind": "converted"`；
  **不要写成 `第M页`** 冒充原文档页。

## 边界
- 只读、不写文件、不改库；带 content-sha256 缓存，重复同文件不重复跑。
- OCR 仍可能对极差扫描件失真——识别结果与你预期严重不符时，标 `manual_review` 交人工，不强行采信。
